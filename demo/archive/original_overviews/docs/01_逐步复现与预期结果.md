# 逐步复现与预期结果

本流程面向没有参与原实验的组员。你先从已保存的原始回答重算结果，理解每步作用。复算并不训练模型。

## 第一步 解压 安装 核验

使用Python3.11或3.12建立新环境，运行根目录README中的安装与 `--verify-only` 命令。会核对题目ID、原图字节、提示词、标签，以及分发文件SHA256。期望打印 `INPUT_AND_FILE_CHECKS_PASSED`。

含义：保证你拿到的题目与我们相同，而不是另抽一批题。检查若失败应先检查解压完整性与文件是否被编辑，不应跳过校验继续报分。

## 第二步 完整离线复算

```bash
python scripts/reproduce_all.py
```

运行结束后终端给出本次输出目录。下文所有路径均以这个 `outputs/<时间戳>/` 为起点。第一次官方评分可能需要几分钟，不要将长输出或符号化简耗时误认为模型还在推理。

### 2A 合并前20题和后80题

原文件位于 `pipelines/qwen_vl/results/qwen_mathvision20_4096/` 与 `qwen_mathvision_extra80_4096/`。不是把两份summary相加：程序先核对推理配置，再按题目ID检查无重复、完整覆盖100题，最后重算总指标。

预期：`qwen_vl/merged/` 100条原始回答；初始保守匹配26/100。日志为 `qwen_merge.log`。20与80属于同一模型、同一协议的互斥题目；预算20题和主实验100题有重叠，不能用同样方式拼成120题。

### 2B 复算Qwen和VL历史复核

使用原项目的同一个答案复核脚本，检查最后完整boxed、唯一选项内容和简单分数等价，不使用模型裁判或新回答。预期Qwen28/100、VL32/100，配对为16共同正确、16 VL改善、12 VL退化、56共同错误。

输出 `qwen_vl/comparison/metrics.csv`、`paired_results.csv`、`REPORT.md` 和 `CASEBOOK.md`。这些仍是历史自定义匹配，不混称官方分数。

### 2C 复算OVR主实验

从ColdStart和RL各100条原始回答运行归档的未修改MathVision官方评分器。该评分器有自己的答案提取启发式，可能从正文提取候选，不能把“判对”自动解释成“模型已完成正确的最终答案”。

预期ColdStart34/100、RL31/100；输出上限命中48/100与70/100。详细分难度、分学科、逐题配对在新生成的 `pipelines/ovr/results/reproduced/<时间戳>/results/reports/cloud_vllm_shared1008192_v1/pilot/`。总验证JSON记录该目录相对路径。

### 2D 复算输出预算实验

固定20题由seed20261025从原100题中选出，各难度4题，排除工程开发重叠ID。程序核对原始流式journal哈希及每题token轨迹，再分别对8192前缀和16384输出评分。

预期：ColdStart4→10题判对、11→0题达到上限；RL6→8题判对、15→4题达到上限。ColdStart6题错转对、0题对转错；RL3题错转对、1题对转错。

`comparison.json` 保存总结果及方法限制，`summary.csv` 保存准确率、95% Wilson区间、自然结束、boxed、think闭合、长度、近似token边界时间；`paired.csv` 给出每题8k/16k转换。

重点案例：ColdStart2911增加预算后收束到boxed384并判对；RL598在8k只留下被判对的正文候选，16k收束到错误boxed E；RL334、612、1118、2816在16k仍截断。请保留失败和退化案例。

### 2E 复算教师与学生长度

教师是公开冷启动数据固定revision的1000条均匀抽样，已含原文；学生是预算实验的40条16k回答。统一tokenizer重新计数think内部文本，排除分隔符和最终答案。

预期平均推理tokens：教师4444.473、ColdStart8672.9、RL10968.75。RL有4条右删失，10968.75是已观测下界；教师的生成终止状态未知。学生RL在17/20题更长。教师文本题与学生图像题不同，不能凭长度认定能力迁移。

### 2F 四模型统一官方重评分

程序将Qwen/VL和OVR的原始回答全部交给同一份官方评分代码，保存 `official_four_models/*-official.jsonl`、`metrics.csv`、`paired_correctness.csv`。交付前复算结果在根目录 `reference_results/`。

作用：消除“用自定义28/32直接对比官方34/31”的评分口径混淆。它仍不消除greedy/sampling、4096/8192、Transformers/vLLM的差异；不应把四模型表写成严格控制的排名。

### 2G 看验收结果

成功标志 `ALL_OFFLINE_REPRODUCTION_VERIFIED`；`VERIFICATION.json` 确认原始文件未变、没有新生成、没有GPU、题目和原图一致，以及OVR逐题评分与历史输出字节一致。

## 第三步 查看案例

`pipelines/ovr/demo/OVR_SHARED100_CASES.html` 可断网打开；Qwen/VL案例位于 `pipelines/qwen_vl/results/model_comparison100/CASEBOOK.md`。对照原图、原始推理、最终答案、截断状态和标准答案。出现“让我再看图”字样只是行为表述，不证明模型真的执行了新的视觉操作。

## 实验分别呈现

原100题主实验、20题8k/16k预算补充实验和教师长度分析分别保留。不要把预算补充实验与原Qwen回答拼成新的同20题模型对比。
